# SchoolRunner — Android app

A clean, native Android wrapper around the **SchoolRunner** React web app.
This is a thin Flutter shell that embeds an Android WebView (via the official
[`webview_flutter`](https://pub.dev/packages/webview_flutter) plugin) pointing
at the deployed web app. The React codebase stays the single source of truth —
there is no duplicated business logic here.

```
┌──────────────────────────────────────────┐
│  Branded splash (indigo, ~0.5 s)         │
│  ┌────────────────────────────────────┐  │
│  │ WebView → https://…vercel.app      │  │
│  │ (React + Supabase + Vercel /api)   │  │
│  └────────────────────────────────────┘  │
│  Offline/error screen + Retry            │
└──────────────────────────────────────────┘
```

## What is in here

| Path | Purpose |
|------|---------|
| `lib/main.dart` | App entry: splash → WebView → error/retry states |
| `android/` | Native Android project (Embedding V2, Kotlin) |
| `android/app/src/main/res/` | Launcher icons (`mipmap-*`), launch splash |
| `android/app/src/main/AndroidManifest.xml` | App label + `INTERNET` permission |
| `android/app/src/release/AndroidManifest.xml` | `INTERNET` permission for release APKs |
| `tool/gen_icons.mjs` | Regenerates the branded launcher icons (pure Node, no deps) |
| `assets/icon/app_icon.png` | 1024 px master icon |

## Building the APK

Requires: [Flutter](https://docs.flutter.dev/get-started/install) with the
Android toolchain (`flutter doctor` should report no issues).

```bash
flutter pub get
flutter analyze

# Debug APK (fast to build, generous app size, good for sideloading):
flutter build apk --debug

# Smaller release APK (recommended for distribution):
flutter build apk --release
```

The APK lands under `build/app/outputs/flutter-apk/`:

| Build        | Typical output                                  |
|--------------|-------------------------------------------------|
| `--debug`    | `build/app/outputs/flutter-apk/app-debug.apk`   |
| `--release`  | `build/app/outputs/flutter-apk/app-release.apk` |

Ready-to-install copies are kept in [`dist/`](./dist):

| File | Sizes |
|------|-------|
| `dist/SchoolRunner-app-v1.0.3-release.apk` | ~42 MB (recommended) |
| `dist/SchoolRunner-app-v1.0.3-debug.apk` | ~144 MB (debug build) |

To install on a phone: copy the APK over and open it in a file manager, or run
`flutter install --device <device-id>` with your Android phone connected with
USB debugging enabled.

## Changing the hosted URL

Edit `kAppUrl` at the top of `lib/main.dart`:

```dart
const String kAppUrl = 'https://schoolrunner.vercel.app';
```

> ⚠️ The URL **must** point at your real SchoolRunner deployment. A wrong URL
> makes the app open the wrong site (or a black page). Verify a URL in a
> browser first — it should show the SchoolRunner landing page with
> "Streamline. Manage. Excel.".

## App shell behaviour

- **Status bar / notch:** the WebView is pushed below the system status bar /
  camera cutout (`MediaQuery` safe-area padding) so the site's top navigation
  is never hidden behind the system bars and is easy to tap. The strip above
  is white.
- **Text size:** the site's root font is scaled to `kWebFontSizePx` (default
  **14px**, down from 16px ≈ 12.5% smaller) on every page load — the whole
  Tailwind/rem-based layout scales with it. Change the constant to taste:

```dart
const double kWebFontSizePx = 14; // smaller = smaller site text
```

## Branding

- **Splash & error screens**: drawn in Flutter (`lib/main.dart`), indigo seed +
  the three-colour brand.
- **Launcher icons**: generated by `tool/gen_icons.mjs`
  (`node tool/gen_icons.mjs`). Design: indigo → teal gradient, amber accent and
  a white graduation mortarboard with an amber tassel.
- **Android launch splash**: solid brand indigo
  (`android/app/src/main/res/values/styles.xml` + `drawable/launch_background.xml`).

## Notes

- **Native bridge for print / CSV / photo upload.** Android's WebView cannot
  perform three things the site relies on: `window.open()`+`window.print()`
  (print), blob `<a download>` (CSV export) and `<input type=file>` (photo
  upload). The app registers a `flutterHost` JavaScript channel; the site
  (`src/lib/mobileHost.js`) hands these to the shell:
  - **CSV** → saved to the device Documents (`getExternalFilesDir(Documents)`
    via a `schoolrunner_host` method channel in `MainActivity.kt`).
  - **Print** → an in-app print sheet with Print + Save to device.
  - **Photo** → the native picker (`file_selector`) returns the chosen file.
  - ⚠️ These web-side hooks only take effect when the **deployed site**
    contains them — after changing `src/`, rebuild and redeploy the web app
    (e.g. `npm run build` + push/deploy to Vercel), then the APK will see it.
- The APK requests the `android.permission.INTERNET` permission (required for
  the WebView + Supabase). It is declared in the main manifest and duplicated
  for the release flavour.
- On Android the WebView is created with **Hybrid Composition**
  (`AndroidWebViewWidgetCreationParams.displayWithHybridComposition`) — the
  default texture-layer display mode can render black on some devices.
- `android/gradle.properties` caps Gradle workers (`org.gradle.workers.max=2`);
  this keeps the AAPT2 daemon pool small on memory-constrained machines,
  which avoids silent AAPT2 crashes during release resource compilation.
- The launcher icons are indexed-colour PNGs generated by `tool/gen_icons.mjs`
  with verified chunk CRCs (Android's AAPT2 rejects icons with invalid CRCs
  on release builds — always validate regenerated icons with the bundled check).
- `flutter build apk --release` signs with the Android debug keys out of the
  box (per the Flutter template), so the APK is intended for **sideloading**,
  not the Play Store. Store distribution needs a real Android signing cert
  (`android/app/build.gradle.kts`).
- The wrapper cannot work fully offline — SchoolRunner's backend (Supabase) is
  remote and the SMS / QR-verification flows live on the Vercel deployment.
